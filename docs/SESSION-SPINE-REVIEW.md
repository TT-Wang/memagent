# Session Spine — Adjudicated Verdict

## 1. Verdict: GO-WITH-CHANGES

The mechanism is sound and all three lenses independently confirm the load-bearing pieces: the byte-level LCP gate cannot be gamed, `_seal_locked` post-redaction rendering is the right seam, `order_ns`/`artifact_order_key` gives resume ordering for free, in-process double-seal is structurally prevented, and mechanical (no-LLM) digest authorship is correct. None of that is relitigated below. But the design as written has three classes of defect that would freeze wrong bytes permanently (durability/redaction/locators), a prefix that is dead on arrival (the pre-spine head is not actually stable), and an over-claimed moat statement (peak is not flat as specified). All are fixable in the doc and Phase A/B scope. Phase A code must not start until the required changes land in SESSION-SPINE-DESIGN.md.

## 2. Required changes before Phase A code (deduped, ranked)

**R1. Pin the digest's durable byte home: a field of `safe_record`, rendered inside `_seal_locked`.**
Render after the indeterminate upgrade (runtime_persistence.py:756-793), embed in `safe_record` before the Artifact is constructed at runtime_persistence.py:832, so the bytes ride the existing 3-stage `prepare_seal → artifacts.put → checkpoint CAS` protocol and its journal replay unchanged. "Append inside coordinator.seal" (MAP §2) is unimplementable — the protocol has no 4th stage or replay branch (persistence.py:1265-1287) — and per-(workspace, task) checkpoint state cannot hold a cross-topic session spine (cli.py:1661, 1677). Resume = scan `kind=='turn'` artifacts for the session (children never call `LocalTurnStore.seal`, but recovery mints `subagent-*` artifacts into the same store, persistence.py:1336 — the filter is mandatory), order by `artifact_order_key`, concatenate the **stored digest strings verbatim — never re-render frozen entries** (a renderer upgrade between save and load would silently rewrite history bytes). Delete the "carry in Slice state" phrasing from Phase A or restate it as a cache of the scan. The live-session return channel is the existing post-seal artifact re-load (cli.py:1667-1670) — single projection, typed-return-lane pattern; no second pre-seal render in cli (it would be pre-redaction, pre-status-upgrade).

**R2. Redaction contract: the digest embeds POST-redaction bytes; "verbatim" means never-paraphrased, not never-redacted.**
The journal header request is already `redact_text(..., preserve_length=True)` (runtime_persistence.py:499) and the artifact brief carries it (runtime_persistence.py:841). Rendering from the live verbatim text writes pasted secrets to disk and re-injects them into every future seed. Rewrite coverage 1 accordingly; one redaction dialect only (`preserve_length=True`, not the mirror's plain dialect at hippocampus.py:336-338). Test: seal a turn whose ask contains a known secret pattern; assert spine bytes and artifact agree and contain no secret.

**R3. One renderer, journal-derivable, serving both seal and crash recovery.**
Coverage 5 is false for SIGKILL: recovery materializes "interrupted" artifacts from journal_events + receipt only (persistence.py:1338-1366) with no access to the dead process's `_pending_seal_records`. Constrain the digest schema so it is derivable from journal-only data (header.user_request + events + receipt) and use ONE renderer at both call sites, with a byte-parity test — the alternative is two renderers, the exact path-asymmetric-wiring bug class the MAP flags for the read side but not its own write side. This forces **R4: drop the pagetable/JSONL preview line as a digest input** — it doesn't exist at digest-render time (append_episode runs after seal, cli.py:1690 vs 1638), is best-effort-swallowed (hippocampus.py:373-376), and never exists in memory-null, the design's own gate config. Manifest subsumption is achieved by the digest *replacing* the preview line, not embedding it. Also spec the degenerate cases in the schema: abort-during-prep (synthetic fallback record, cli.py:1573-1576) renders from header+receipt only; `waiting_peer` entries are marked open/parked, never presented as concluded.

**R4. Frozen locators cite `artifact_id`, never positional turn-N.**
`@sliceagent/history/turn-N.md` resolves `_current()[N-1]` filtered to the CURRENT session_id (contextfs.py:736-740, 811-816): after restart every frozen locator dangles; one unreadable artifact silently shifts all later frozen locators onto the wrong turn; three numbering schemes already diverge (artifact position vs EpisodeSink._turn vs target.turns). Machine locator = immutable artifact_id (resolvable in any session via `sessions/<key>/<artifact_id>.md`); a human-readable N is display text only.

**R5. Answer the segment model (MAP Q3) in the design, not the open-questions list.**
One logical turn seals multiple segments into TWO stores across a workspace handoff (cli.py:1581-1588, 2350, 2607), so neither disk contains the whole logical turn and coverage 7's byte-identical-resume claim is false as written. Decide: per-segment entries (dedupe the repeated ask, define entries as segment-scoped) or per-logical-turn at the terminal segment (define crash-interrupted continuations). Specify the cross-workspace carrier for prior digests — the `workspace_continue` admission record (cli.py:1499-1508) is the natural vehicle — or explicitly scope byte-identical resume to single-workspace sessions.

**R6. Actually freeze the pre-spine head, or the spine never gets a warm prefix.**
Two live falsifiers of DESIGN:34-36: (a) the system prefix is rebuilt per segment with live git bytes (branch/dirty/HEAD line, sensory_cortex.py:280-287 via seed.py:366-372), a re-walked repo map, and the plan-mode overlay — any commit or edit kills every downstream byte; production is strictly worse than the 39-44% harness baseline. (b) `lessons_memo` is reconstructed every `make_build_slice` call keyed on the NEW request (seed.py:489-498) — the memory region's bytes change every turn while pinned pre-spine. Fix: compute the system prefix once per session/epoch; move the git line to the tail (git_worktree_state already covers live git); pin the repo map per epoch; snapshot memory recall per topic/session or move memory behind the spine into the tail. Add system-message and memory-region byte-diff assertions to the probe gate.

**R7. Resolve the degradation contradiction: all-or-nothing plus a per-turn latch.**
DESIGN:94-104 says drop-oldest-first; MAP:82 says the inverse — an unresolved direct contradiction, and both partial policies lose: oldest-first rewrites front bytes (cache-worst), newest-first evicts the most relevant entries and keeps turn-1 resident (violates bound-is-relevance-not-size, gotten wrong twice already). Adjudication: under pressure the spine degrades **whole-spine → single index locator** (the existing drop-whole FULL+LOCATOR pattern, MAP §4.3's own third option) — no relevance inversion, no front-byte rewrite in normal operation, and the recent context lives in the paired reserve (R8) anyway. Add a **per-turn latch** (once degraded this turn, stays degraded; the stateless per-call controller at context.py:267-283 currently springs entries back mid-turn) — acknowledge honestly that the latch IS a stateful controller change with its own restart story. Give the spine priority above every volatile-tail region so the tail degrades first. Relevance answer for CORE-DESIGN:155-159's region-legitimacy test: entries whose topic is closed compact earlier than budget (digests already carry topic id). Add an oscillation probe under fluctuating capacity.

**R8. Keep the paired verbatim reserve; the spine subsumes only turns OLDER than the reserve.**
The reserve holds paired exchanges precisely because deixis resolves against ASSISTANT text ("go with your recommendation" at turn 8 against options enumerated in turn 5's reply; regions.py:54-63, context_compiler.py:226-228), and the locator fallback is a measured-dead channel (~0 recall on coding turns, context_compiler.py:153-155). Cache wins live in turns 13+ where transcript growth is anyway. Amend the subsumption table; the reserve stays in the volatile tail per today's contract. Corollary: a giant pasted ask degrades to a bounded verbatim HEAD + locator with a **loud** truncation marker (the recall-ring-truncation confab shipped twice via silent caps), never locator-only.

**R9. State the peak math and fix the boundedness claim.**
As specified, resident spine ≈ B + (N/35)·0.4k — linear in session length, with no generation-2 policy; the seed at budget is +3-5k over today's flat ~11k. Cost always wins; **peak** is where the moat's headline metric ("flat per-turn peak") breaks. Required: (a) put the resident-delta arithmetic in the doc; (b) epoch summaries count against the same budget, and are **purely mechanical** (turn-id range + topic ids + on-disk epoch-index locator, zero semantic summarization — this simultaneously rescues CORE-DESIGN.md:90-92's "no routine summarization" claim); (c) generation-2 compaction or hard-cap collapse to the index locator bounds resident spine; (d) restate the public claim — peak ramps to head+B then holds — and re-baseline the README/benchmark framing before the meter gate is declared green.

**R10. Digest content: provenance-grade facts only; determinism law L7.**
Ban current-truth claims ("key findings" out of DESIGN:52-53) — frozen semantic claims reproduce the stale-transcript pathology in miniature and conflict with curated volatile FINDINGS; adopt the "verbatim claim; not world evidence" epistemic header; corrections are appended entries citing the corrected artifact_id, never edits. Law L7: the digest is a pure function of already-durable inputs — no clock (Artifact.timestamp is `now()` at seal), no counters, no environment — because a one-byte difference converts idempotent recovery replay into ArtifactConflictError (persistence.py:431, 592-593). Render-twice-assert-equal test at both call sites.

**R11. Graph lane: decide, don't defer (MAP Q6).**
The spine renders on EVERY turn in BOTH lanes, never gated on `needs_history`; its region name is added to `compile_active_context`'s always-selected set (per-turn presence flipping of pre-spine regions is itself a byte break, context_compiler.py:334-349). ACTIVE WORK (order=-1, slot 0, mutates per step, embeds graph.revision) is a live control surface — by the design's own taxonomy it moves below the spine into the volatile tail. Count the graph-lane resident cost in the meter gate.

**R12. Upgrade the quality gate to what the MAP already mandates.**
DESIGN:82-84 (s2/s5 × n=2) contradicts MAP:94 ("the 8-scenario matrix is a mandatory gate"). The s2/s5 gate detects execution destabilization, not the deixis/correction/tone regression class R8 protects against — that class was historically found only by usersim leading-prompt probes. Gate = 8-scenario matrix + a conversational probe (existing usersim + evals/convo_h2h.py) exercising turn-5-referent deixis, ordinal selection, and correction-following, spine on/off.

## 3. Amended Phase A + B implementation checklist

### Phase A — Spine store (write side)

1. Digest schema module: pure function of (redacted journal header, journal events, receipt, order_ns, topic id, segment metadata per R5). Fields: post-redaction verbatim ask, outcome/status, files touched, artifact_id locator, topic/segment ids, epistemic header. No pagetable line, no "key findings", no clock, no counters (R3, R4, R10).
2. Render inside `_seal_locked` after the indeterminate upgrade; embed as a `safe_record` field before Artifact construction at runtime_persistence.py:832 (R1).
3. Same renderer invoked from `coordinator.recover` for crash-interrupted artifacts; byte-parity test between the two call sites (R3).
4. Degenerate-case rendering: abort-during-prep (header+receipt only), waiting_peer marked open/parked (R3).
5. Segment model per R5 decision, incl. cross-workspace digest carrier via the workspace_continue admission record; `_pending_seal_records.clear()` interaction documented.
6. Resume rebuild: scan `kind=='turn'` artifacts (filter subagent-*), sort by `artifact_order_key`, concatenate stored strings verbatim; live-session append point = the post-seal artifact re-load only (R1).
7. Tests: L7 render-twice determinism at seal and recover; secret-pattern redaction test; resume byte-identity test that upgrades the renderer between save and load; workspace-handoff resume test (or documented single-workspace scoping).

### Phase B — Seed integration (read side)

8. Freeze the head first: system prefix once per session/epoch; git line and plan overlay out of the pre-spine bytes; repo map pinned per epoch; memory recall snapshotted per topic/session or relocated to the tail (R6). This lands BEFORE the spine region — otherwise the probe gate measures nothing.
9. SESSION SPINE region: frozen concatenation verbatim, artifact_id locators, priority above all volatile-tail regions, present every turn in both lanes; region name added to `compile_active_context` selection; ACTIVE WORK relocated below the spine (R7, R11).
10. Elasticity: whole-spine ↔ index-locator alternative only; per-turn degradation latch in the controller (stateful — spec its restart behavior); no partial eviction in either direction (R7).
11. Volatile tail enumerated exhaustively: paired verbatim reserve (kept per R8), current request, progress, world, live truth, git line, "…older"/"+N earlier" counters, receipt block. Invariant + grep audit: no relative-age or count text at or before the spine.
12. Admission journal + analytics mapping for the new region name (existing coverage 8).
13. Gates, all pre-registered: byte probe 40%→≥80% incl. system/memory byte-diff assertions and the fluctuating-capacity oscillation probe; 8-scenario matrix; usersim deixis/correction probe; meter with graph-lane resident cost counted and the re-baselined peak claim (R9, R12).

## 4. Deferred — and why that is safe

- **Epoch compaction implementation (Phase D)** — safe to defer *implementation* because R9 fixes the *policy and claim* now: mechanical summary format, budget accounting, and gen-2/hard-cap are specified in the doc, and sessions under ~30-40 turns never hit the trigger. What was not safe — shipping the moat claim unbaselined — is pulled forward into R9.
- **Manifest/window subsumption (Phase C)** — deferral is safe because R4 already makes the digest self-contained; until C lands the manifest is merely redundant, not wrong. The "+N earlier" counter dies with C; until then it lives in the tail per item 11.
- **T4 alias byte interaction (MAP Q7)** — both structures are append-only; the byte-level verification belongs in the Phase B probe run, and a failure there degrades cache hit rate, not correctness.
- **`steps[].slice` artifact slimming (MAP Q8)** — pure storage-weight optimization behind a consumer audit; no coupling to spine correctness.
- **The pre-existing three-way turn-numbering divergence** (artifact position vs EpisodeSink._turn vs target.turns; a live wrong-recall risk in today's manifest) — safe to decouple *only because* R4 removes positional numbers from frozen bytes. It should be fixed as its own task, since it affects the current manifest independent of the spine; it is no longer on the spine's critical path.
- **Kimi-ceiling gap quantification (MAP Q9)** — reporting framing, not mechanism; needed before publishing results, not before Phase A code.

One consistency pass is also required on the docs themselves before Phase A: reconcile DESIGN:82-84 vs MAP:94 (gate), DESIGN:94-104 vs MAP:82 (degradation), and MAP:23's "zero controller changes" vs its own §4.3 latch requirement — all three pairs currently let a reviewer cite whichever half supports their preference.
